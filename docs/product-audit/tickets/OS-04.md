# OS-04 — 구매 시점 라이선스·에셋 버전 불변 스냅샷

우선순위 **P0** / 담당 **팀원 B** / **1.5인일** / 난이도 **L** / 불확실성 **중간** / 상태 **Ready after dependencies**

## 문제와 사용자 가치 · 현재 근거
주문 금액·수수료 snapshot은 있으나 license_snapshot은 없다. 게시물 수정 후 구매 권리 설명이 바뀔 위험이다.

현재 근거: [현재 상태](../01_CURRENT_STATE_AUDIT.md), [Gap](../03_GAP_AND_UX_AUDIT.md). 코드 탐색 경로: `supabase/migrations; apps/web/src/lib/server/api.ts; apps/web/src/components/listing-detail.tsx; apps/web/src/components/account-panels.tsx`. 기준 SHA에서 해당 화면/API와 고정 fixture를 먼저 재현하고, 이미 충족한 부분은 보존한다. 신규 결함으로 단정하기 전에 현재 테스트와 비교한다.

## 구현 범위
주문·entitlement에 license/version/hash/판매자/권리 동의 시점 snapshot; 구매 영수증 표시; 기존 주문은 unknown legacy로 backfill하고 추측 금지.

제외: 이 범위 밖의 전면 재설계, 새로운 모델·외부 API 도입, 운영 DB·DNS·실과금·프로덕션 배포.

## 접근·파일·의존성·충돌
재사용: 현재 Next/React/Zod/Supabase, Three/R3F/glTF-Transform, sharp, 기존 Worker 계약. 라이브러리 선택은 [가능성](../04_DIFFERENTIATION_AND_FEASIBILITY.md)의 기능/버전 제한을 따른다.
파일: `supabase/migrations; apps/web/src/lib/server/api.ts; apps/web/src/components/listing-detail.tsx; apps/web/src/components/account-panels.tsx`. 선행: OS-01. API 공통 파일 `api.ts`, shared contracts, migrations는 PR 단위 직렬 통합하고 각각 전용 helper로 분리한다. migration 번호는 merge 직전 확인한다.

## API/DB/오류·취소 계약
기존 API path와 schema를 우선 재사용한다. 추가 필드는 additive typed version으로 검증하고 client/server 양쪽에 동일 fixture를 둔다. owner_id는 세션에서 도출하고 입력값을 신뢰하지 않는다. unauthorized=401, foreign/not-found=404, stale/conflict=409, invalid=400/422, retryable unavailable=503을 기존 convention에 맞춘다. timeout은 성공으로 간주하지 않고 서버 상태를 재조회한다. mutation은 idempotent하며 terminal 상태를 역행하지 않는다. 크레딧·결제·파일 권한의 확정 권한은 서버에 둔다.

## 티켓별 구체 계약·재현 fixture
additive migration 후보: order license_snapshot jsonb(schema_version,license_code,license_text_hash,artifact_id,artifact_sha256,seller_id,rights_consent_at), entitlement source_order_id/version 불변 참조. 이름은 기존 schema 확인 후 결정한다. 서버 transaction 내 주문 생성 시 snapshot 확정, provider callback은 수정 금지. legacy 누락값은 unknown 표기. buyer 접근만 허용하며 seller 가격변경은 주문 불변.

## Acceptance Criteria
- Given 고정 fixture와 본인 세션, When 관련 동작을 실행하면, Then 주문 후 판매자가 라이선스를 변경해도 기존 구매 권리 snapshot은 변하지 않는다.
- Given 고정 fixture와 본인 세션, When 관련 동작을 실행하면, Then 환불된 구매자는 새 다운로드 URL 발급이 거부되고 기존 만료 정책을 안내한다.
- Given 고정 fixture와 본인 세션, When 관련 동작을 실행하면, Then 타인 주문 조회와 snapshot 수정은 RLS/API 모두 거부되며 중복 confirm도 한 권한만 만든다.

## 검증 명령과 제출 증거
`npm ci`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`를 실행한다. Python 변경은 `cd gpu-worker && .venv/bin/python -m pytest tests`(가상환경 경로는 doctor로 확인)를 추가한다. E2E는 `npx playwright test`이며 기본 포트3000과 `NEXT_PUBLIC_APP_URL`을 맞춘다. 기존 실행 서버3010을 쓸 때는 `npx playwright test --config artifacts/launch-v5/playwright.release.config.ts`와 APP_URL3010을 함께 사용한다. 선택 suite만 통과하고 전체 통과로 보고하지 않는다.

각 AC의 성공/실패 fixture, 다른 계정 권한 거부, 요청 재전송을 자동화하고 `artifacts/OS-04/`에 명령·exit code·SHA·redacted 로그를 남긴다. UI는 360/768/1440px 실제 Chromium 캡처와 키보드/axe 검수를 제출한다. 실제 GPU 결과와 mock 결과를 분리한다. 실제 GPU가 필요하지만 접근할 수 없으면 mock 통과와 실GPU 미검증을 따로 보고한다.
