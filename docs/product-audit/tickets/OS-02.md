# OS-02 — 가입 확인·비밀번호 재설정의 이탈 복구

우선순위 **P0** / 담당 **팀원 B** / **1인일** / 난이도 **M** / 불확실성 **중간** / 상태 **Ready after dependencies**

## 문제와 사용자 가치 · 현재 근거
로컬 이메일 E2E는 있지만 외부 신규 가입 SMTP는 미검증. 관리자 확인 계정으로 일반 가입 성공을 주장할 수 없다.

현재 근거: [현재 상태](../01_CURRENT_STATE_AUDIT.md), [Gap](../03_GAP_AND_UX_AUDIT.md). 코드 탐색 경로: `apps/web/src/components/auth-form.tsx; apps/web/src/app/auth; tests/e2e/auth-email.spec.ts`. 기준 SHA에서 해당 화면/API와 고정 fixture를 먼저 재현하고, 이미 충족한 부분은 보존한다. 신규 결함으로 단정하기 전에 현재 테스트와 비교한다.

## 구현 범위
Mailpit 기반 만료/중복 링크·재발송 cooldown·returnTo allowlist·메일 대기 화면과 접근성 검증; Owner SMTP 체크리스트.

제외: 이 범위 밖의 전면 재설계, 새로운 모델·외부 API 도입, 운영 DB·DNS·실과금·프로덕션 배포.

## 접근·파일·의존성·충돌
재사용: 현재 Next/React/Zod/Supabase, Three/R3F/glTF-Transform, sharp, 기존 Worker 계약. 라이브러리 선택은 [가능성](../04_DIFFERENTIATION_AND_FEASIBILITY.md)의 기능/버전 제한을 따른다.
파일: `apps/web/src/components/auth-form.tsx; apps/web/src/app/auth; tests/e2e/auth-email.spec.ts`. 선행: 없음. API 공통 파일 `api.ts`, shared contracts, migrations는 PR 단위 직렬 통합하고 각각 전용 helper로 분리한다. migration 번호는 merge 직전 확인한다.

## API/DB/오류·취소 계약
기존 API path와 schema를 우선 재사용한다. 추가 필드는 additive typed version으로 검증하고 client/server 양쪽에 동일 fixture를 둔다. owner_id는 세션에서 도출하고 입력값을 신뢰하지 않는다. unauthorized=401, foreign/not-found=404, stale/conflict=409, invalid=400/422, retryable unavailable=503을 기존 convention에 맞춘다. timeout은 성공으로 간주하지 않고 서버 상태를 재조회한다. mutation은 idempotent하며 terminal 상태를 역행하지 않는다. 크레딧·결제·파일 권한의 확정 권한은 서버에 둔다.

## 티켓별 구체 계약·재현 fixture
Supabase signUp/resend/resetPasswordForEmail/updateUser의 현 callback 경로 유지. redirect allowlist는 localhost configured APP_URL만, raw email enumeration을 유발하는 존재 여부 노출 금지. 만료/동일링크 재사용/메일발송 실패/429 재발송 fixture. SMTP credential 설정 코드는 추가하지 않는다.

## Acceptance Criteria
- Given 고정 fixture와 본인 세션, When 관련 동작을 실행하면, Then 가입 후 미확인 상태에서는 보호 API 접근이 차단되고 재발송 안내가 보인다.
- Given 고정 fixture와 본인 세션, When 관련 동작을 실행하면, Then 만료된 reset 링크는 재발송으로 복구하며 기존 세션 권한을 부여하지 않는다.
- Given 외부 returnTo를 넣으 조건, When 해당 사용자/API 경로를 실행하면, Then 외부 returnTo를 넣으면 허용된 로컬 경로로만 이동한다.

GitHub main은 앱 기준이 아니다. 최초 `git status`, `git log -1`, 루트/하위 AGENTS와 docs/product-audit/01_CURRENT_STATE_AUDIT.md를 읽고, 선행 PR이 포함된 팀 통합 브랜치에서 이 티켓 전용 `ticket/OS-02` 브랜치를 만든다. 다른 사람의 미커밋 변경을 덮어쓰지 않는다. ## 검증 명령과 제출 증거
`npm ci`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`를 실행한다. Python 변경은 `cd gpu-worker && .venv/bin/python -m pytest tests`(가상환경 경로는 doctor로 확인)를 추가한다. E2E는 `npx playwright test`이며 기본 포트3000과 `NEXT_PUBLIC_APP_URL`을 맞춘다. 기존 실행 서버3010을 쓸 때는 `npx playwright test --config artifacts/launch-v5/playwright.release.config.ts`와 APP_URL3010을 함께 사용한다. 선택 suite만 통과하고 전체 통과로 보고하지 않는다.

각 AC의 성공/실패 fixture, 다른 계정 권한 거부, 요청 재전송을 자동화하고 `artifacts/OS-02/`에 명령·exit code·SHA·redacted 로그를 남긴다. UI는 360/768/1440px 실제 Chromium 캡처와 키보드/axe 검수를 제출한다. 실제 GPU 결과와 mock 결과를 분리한다. 실제 GPU가 필요하지만 접근할 수 없으면 mock 통과와 실GPU 미검증을 따로 보고한다.

## Definition of Done · 위험 · Rollback
모든 AC와 관련 회귀가 통과하고 코드/문서/계약이 일치해야 완료다. 리뷰어는 다른 팀원. 실패·보류를 완료로 바꾸지 않는다. migration은 additive하며 로컬 upgrade 검증을 포함하고 원장 파괴적 down migration은 금지한다. UI/새 경로 feature gate로 되돌릴 수 있어야 하며 기존 데이터·private storage·원본 GLB·작업 큐를 보존한다. 실제 활성화는 Owner 승인 대상이다.
