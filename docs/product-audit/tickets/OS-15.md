# OS-15 — 장면 전체 Mesh 품질 기준과 파편 재현 연구
P2 / 담당 팀원 A / **2인일 timebox** / 난이도 L / 불확실성 높음 / **이번 Sprint 제외**
## 문제·근거·재현
32장 학습·추출은 성공했으나 장면 시각 품질 탈락. `gpu-worker/objectscan_worker; docs/validation/gw-scene32.json`를 기준 SHA7ee1709에서 확인한다. docs/validation의 기존 실패 fixture를 먼저 재현한다. OS-12 후 착수; 모델 연구는 OWN-02 권리 확인 선행.
## In / Out · 접근·관련 파일
기존 입력에서 등록 카메라/연결성/UV 단계별 실패 분리; textured Mesh와 splat 구분; 임의 활성화 금지. 관련 파일: `gpu-worker/objectscan_worker; docs/validation/gw-scene32.json`. [기술 가능성](../04_DIFFERENTIATION_AND_FEASIBILITY.md) 참조. 기존 pinned 환경과 로컬 전용 입력을 사용한다. 모델 교체·추가 유료 API·배포·고급 기능 완제품 보장은 제외한다. api.ts/shared/migration 변경은 선행 계약 PR 뒤 직렬 통합.
## 계약·오류·취소
입력/출력 manifest에 SHA·파일 hash·단위·UV/texture·지원 여부를 기록한다. 불충분한 pose·OOM·취소·불법 입력은 각각 명시적 실패로 기록하고 원본/기존 권한을 보존한다. GPU 동시1, CPU/파일 예산 유지. 정합/품질 미달을 성공 UI로 바꾸지 않는다.
## Acceptance Criteria
- Given 기존 실패 입력, When 고정 환경으로 재현하면, Then baseline 로그·원인 가설이 남는다.
- Given 제안 변경, When 성공/실패 fixture를 각각 실행하면, Then UV/texture·권한·예산·취소 결과를 확인할 수 있다.
- Given 2일 timebox 종료, When 결과를 정리하면, Then 성공 여부와 무관하게 재현 명령·증거·후속 구현 견적·활성화 금지 조건을 제출한다.

## 공통 실행 조건
기준 앱은 `debc1f7`, 코드·증거 기준 브랜치는 `feat/service-launch-v5`의 `7ee1709`다. GitHub main은 앱 기준이 아니다. 최초 `git status`, `git log -1`, 루트/하위 AGENTS와 docs/product-audit/01_CURRENT_STATE_AUDIT.md를 읽고, 선행 PR이 포함된 팀 통합 브랜치에서 이 티켓 전용 `ticket/OS-15` 브랜치를 만든다. 다른 사람의 미커밋 변경을 덮어쓰지 않는다. A/B는 둘 다 풀스택이며 기존 Track A/B/C 역할 구분을 적용하지 않는다.

실계정 인증·키 입력·외부 설정·배포·DNS는 Owner만 수행한다. 개발자는 로컬 disposable Supabase + Mailpit + provider mock을 사용한다. 운영 DB reset 금지. 비밀 키·JWT·signed URL을 로그/스크린샷/Git에 넣지 않는다. 내부 모델명은 고객 화면에 표시하지 않는다.

## 검증 명령과 제출 증거
`npm ci`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`를 실행한다. Python 변경은 `cd gpu-worker && .venv/bin/python -m pytest tests`(가상환경 경로는 doctor로 확인)를 추가한다. E2E는 `npx playwright test`이며 기본 포트3000과 `NEXT_PUBLIC_APP_URL`을 맞춘다. 기존 실행 서버3010을 쓸 때는 `npx playwright test --config artifacts/launch-v5/playwright.release.config.ts`와 APP_URL3010을 함께 사용한다. 선택 suite만 통과하고 전체 통과로 보고하지 않는다.

각 AC의 성공/실패 fixture, 다른 계정 권한 거부, 요청 재전송을 자동화하고 `artifacts/OS-15/`에 명령·exit code·SHA·redacted 로그를 남긴다. UI는 360/768/1440px 실제 Chromium 캡처와 키보드/axe 검수를 제출한다. 실제 GPU 결과와 mock 결과를 분리한다. 실제 GPU가 필요하지만 접근할 수 없으면 mock 통과와 실GPU 미검증을 따로 보고한다.

## Definition of Done · 위험 · Rollback
모든 AC와 관련 회귀가 통과하고 코드/문서/계약이 일치해야 완료다. 리뷰어는 다른 팀원. 실패·보류를 완료로 바꾸지 않는다. migration은 additive하며 로컬 upgrade 검증을 포함하고 원장 파괴적 down migration은 금지한다. UI/새 경로 feature gate로 되돌릴 수 있어야 하며 기존 데이터·private storage·원본 GLB·작업 큐를 보존한다. 실제 활성화는 Owner 승인 대상이다.
