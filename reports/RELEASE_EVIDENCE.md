## Failures found, repaired and rechecked

1. First local CUDA output was valid, but strict result API rejected a diagnostic `execution_profile` field. Worker now sends only contract fields;26 Python tests and the complete hosted reconstruction pass.
2. Local model loading caused API/RAM pressure. Web/DB were isolated on hosted infrastructure; hosted heartbeat/polling and actual generation completed. Earlier fenced local job was reconciled only after child processes stopped; no TTL-only GPU recycling.
3. First hosted upload assertion used5s; actual cloud upload was still in progress.30s allowance passed without falsely finishing uploads.
4. Hosted TEST approval was denied by Toss IP access policy from the default US Vercel region. Seoul `icn1` deployment confirmed the same real authenticated order through the browser callback, then actual purchase/refund passed. No Toss access policy was weakened. This was callback recovery across deployments; a fresh post-cutover automatic provider return was not separately re-authenticated. New result UI safely retries the same server-verified order.
5. Three local regression cases failed because QA3010 was built with APP_URL3000. Explicit3010 build/runtime configuration fixed the origin mismatch; all9 cases pass. Same-origin checks were preserved.
6. Two deployment bypass tokens appeared in diagnostic output. Both were revoked and replaced; actual old-token HTTP302/replacement200 verified. SSO protection retained. No Toss/DB secret printed. Private values are absent from source and reports.
